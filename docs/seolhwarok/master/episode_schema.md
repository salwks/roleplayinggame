# Episode File Schema v2

각 에피소드 파일은 아래 구조를 기준으로 누적한다.

## A. 기본 메타
1. ID / 표준 설화명 / 부제
2. 원전 계열 및 검증 상태
3. 지역
4. 원전 시대
5. 게임 시점: 현재 / 잔향 / 현현 / 혼합
6. 등급: A / B / C / D / W
7. 예상 플레이타임
8. 문서 상태: Concept / Scenario / Gameplay Scenario / Final

## B. 원전과 개입 원칙
9. 원전 핵심 사건
10. 절대 변경하지 않을 요소
11. 원작 인물이 반드시 직접 해야 하는 행동
12. 플레이어 역할과 개입 한계

## C. 전체 플레이 구조
13. 에피소드 감정 곡선
14. 큰 Mission/Chapter 구성
15. 공통 Gameplay Module
16. 시그니처 플레이 시스템
17. 재사용 가능한 공통 시스템

## D. 주요 세트피스 상세
각 주요 세트피스마다 아래 항목을 작성한다.

### 상황
무슨 일이 발생하는가.

### 원작 인물 행동
설화의 핵심 행동 중 원작 인물이 직접 수행하는 것은 무엇인가.

### 플레이어 행동
패드/키보드를 잡은 플레이어가 실제로 무엇을 하는가.
'조사한다', '도와준다' 같은 추상어 대신 이동/잡기/밀기/선택/회피/전투 등으로 명시한다.

### 화면 표현
카메라, NPC, 소리, 환경, 오브젝트가 실제 게임 화면에서 어떻게 보이는가.

### Godot 구현 방식
- CharacterBody3D
- RigidBody3D
- Area3D
- AnimationTree / AnimationPlayer
- NavigationAgent3D
- Path3D / PathFollow3D
- GPUParticles3D
- 단계식 Mesh 교체
- Shader
- UI/Flag
등 중 실제 구현 방식을 기록한다.

### 실제 물리 / 연출 구분
대규모 현상을 모두 물리 시뮬레이션하지 않는다.
플레이어가 직접 만지는 핵심 오브젝트만 실제 물리를 적용하고 규모감은 VFX/애니메이션/상태 전환으로 만든다.

### 실패/보정
실패 시 원전 핵심 사건을 무너뜨리는지, 난도/관계/연출만 변화하는지 기록한다.

### 서사적 의미
왜 이 플레이가 이 설화에 필요한지 설명한다.

## 제작 원칙
- 퀘스트 숫자를 늘리기 위해 작은 행동을 독립 미션으로 쪼개지 않는다.
- 여러 작은 행동은 가능한 한 하나의 큰 상황/세트피스 안에 묶는다.
- 대사보다 플레이어가 실제로 하는 행동을 먼저 설계한다.
- 원전의 핵심 행동을 플레이어에게 빼앗기지 않는다.
- 같은 시스템을 다른 의미로 재사용하는 것을 우선한다.
- Godot에서 대규모 물리 연산이 필요한 장면은 제한 물리 + 연출형 세트피스로 대체한다.
